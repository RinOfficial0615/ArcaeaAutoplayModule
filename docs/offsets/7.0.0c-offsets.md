## Scenecontrol gate (custom-chart effects)

The engine keeps a full runtime for the per-timing track/camera commands
inherited from the April-Fools 2022 Dynamix collaboration chart
(`dynamix_conflict`; RTTI names survive: `LogicSceneControl`,
`LogicCameraControl`, `GameSceneVisualControlHandler::handleLogicSceneControl`).
The aff parser tokenizes `scenecontrol` for every chart, but execution is
gated by one boolean in the play-context object at `+0x110`, and only that
event chart ever raises it. The gate is read through an 8-byte getter,
`sub_E6F768 = LDRB W0,[X0,#0x110]; RET`, from ~10 consumers:

- `sub_B77F20` (play setup): assigns `img/track_black.png` +
  `img/track_break_mask.png` via the direct `"dynamix_conflict"` string
  compare, then scales lane geometry off the flag.
- `sub_E80B30`: touch→lane mapping; when armed it consults a transform
  schedule object instead of fixed ±425/±850 lane bounds.
- `Gameplay_tryTapJudgementForTouch` (`0x109F144`): two consults during
  hit testing.

This is the same gate family as the community's 4.x fix ("search immediate
264 / LDRB +0x108, force the getter to `MOV W0,#1`"); on ARM64 the compilers
kept every check behind this single getter call. While custom charts are
installed the module swaps those 8 bytes for `MOV W0,#1; RET`
(`kScenecontrolGateAlwaysTrue`) inside one verified `PatchTransaction`. With
no scheduled transforms the consumers reduce to vanilla behavior, so official
charts are unaffected; a failed patch is non-fatal and only leaves the effects
dormant. Profiles before 7.0.0c keep a zero offset and skip the patch. The
community's separate green-snake remap (`CMP W1,#2 → #4`) was not reproduced
on 7.0.0c in this pass and is not needed for camera/track scheduling.

vtable references, so an in-place overwrite is call-safe.

## Object-layout drift in 7.0.0c

The base zone (`Timer`, `Gameplay`, common `LogicNote` fields through
`longTouchState`, `NotePosition`, `TouchLike`, `HttpRequest`, `HttpResponse`,
and the whole custom-chart `Song`/`SongDifficulty`/registry family) is
unchanged; all of those offsets are pinned by shared assertions in
`src/game/GameStructs.hpp`.

One pointer-sized member was inserted into the note-family *derived* area
between `active`(+0x54, unmoved) and `isVoid`, shifting every later derived
member by +8. Verified directly from matched code pairs:

| Member | ≤ 6.16.8c | 7.0.0c | Evidence |
|---|---:|---:|---|
| `LogicArcNote::isVoid` | `+156` | `+164` | every `ldr w,[..,#0x9C]` beside an arc-typeinfo reference becomes `#0xA4` (old has no surviving site) |
| `arc arctap child position read` | `child+120` | `child+128` | `tryTapJudgementForTouch` hit-test loop |
| `LogicHoldNote::headActivated` | `+160` | `+168` | `tryTapJudgementForTouch` writes `v46[160]` → `v46[168]` after the hold cast |
| `LogicArcNote::activeNow` | `+200` | `+208` | hit-test gating reads move with isVoid |
| arc runtime x/y floats | `+204/+208` | `+212/+216` | sole float-pair access window `(204,208)` disappears; a single `(212,216)` window appears |

Consumers go through version-aware selectors (`cfg::autoplay::*Offset(version)`
in `src/config/AutoplayConfig.h`, applied by `src/game/GameTypes.hpp`); the
active row is latched from the resolved profile before any feature arms hooks.

Residual risk: `LogicNote::longTouchState` (+92) and `playSceneCtx` (+64) show
no contradicting evidence across all matched functions but were not tied to a
dedicated establishing site in this pass; they stay on the shared row.

## Songlist / AFF format notes in 7.0.0c

Cross-checked against the live `songlist`, the two konzetsu charts
(`cataclysmcry` / `deinosphainein`), and the songlist parse body
`sub_CCE050`:

- Difficulty slots stay five. Every `ratingClass` funnels through
  `sub_1194380` (`return rc >= 5 ? 1 : rc`), so there is no slot-count or
  layout change to the custom-chart family.
- The new Inscribed difficulty rides `ratingClass: 3` plus a display-only
  `ratingClassAlias` (=1) and `legacy11`. Both keys are read inside
  `sub_CCE050` (string xrefs at `0xCD06F4` / `0xCD10A4`) and forwarded into
  the per-difficulty constructor `sub_8BDEE8`; missing keys default to
  zero/false. Generated custom entries therefore stay valid without them,
  and the module keeps emitting plain `ratingClass` entries.
- Official `side` values now span 0..4 (2 since v4.0 epilogue songs, 3
  since v6.0 lephon/designant, 4 first in konzetsu).
  `cfg::custom_charts::kMaximumSide` moved 2 → 4 so raw-zip metadata import
  no longer falls back to defaults on those entries.
- AFF additions all pass through unmodified: arc color index 3 (the gold
  guide arcs in `cataclysmcry_3`) survives because the normalizer never
  rewrites the color field, and timing-group labels are arbitrary
  identifiers in the official grammar (`timinggroup(tracecoleeee00)` ships
  in `deinosphainein_3`). Runtime analysis of the group-property matcher
  shows it only reacts to `noinput`, `fadingholds` and
  `anglex<tenths>`/`angley<tenths>`, so unknown labels are inert and
  `AffNormalizer` now keeps any identifier-shaped label verbatim instead of
  dropping it (labels spelling lexer keywords such as `true` are still
  rejected).
- The official parser grammar itself is unchanged from 6.x. The lexer
  keyword classifier (`sub_10DC294`) recognizes exactly the same thirteen
  reserved words (`timing`, `hold`, `arc`, `camera`, `scenecontrol`,
  `timinggroup`, `rgb`, `flick`, `arctap`/`at`, `true`, `false`,
  `designant`) — there is no new command or flag word. As a cross-check,
  every line of all eight sample charts validates against
  `aff::CheckOfficial` unchanged (6877 arcs, argc only ever 10 with an
  optional trailing positive float, colors 0/1/3, group labels empty /
  single ident); the new 7.0-shaped fixture lives in
  `tests/aff_official_parser_host_test.cpp`.

Install-time checks cover the `0x105F0F4` BL, both digest guards, and the
scenecontrol gate bytes together.
`python tests/verify_profile.py` validates this profile against the exact
SHA-256 above when `../7.0.0c/libcocos2dcpp.so` is present.
