# Arcaea 7.0.0c 偏移证据

语言：[English](7.0.0c-offsets.md) | 简体中文

目标：`libcocos2dcpp.so`（ARM64，已剥符号）

- SHA-256：`8526a8dad5110e5db3a103e3cc3a8acd33d8faa57d0a53ae6628ba4440948837`

所有消费位点均由 6.16.8c profile 经「指令掩码匹配」（通配 PC 相对操作数与
立即数，保留操作码与寄存器域）迁移，并逐个在 IDA 中复核：函数头指纹、
`ShowJudgementEffectAtNote` 的 `EARLY`/`LATE` 字符串锚定、调用图一致性
（`processLogicNotes` 内部调用的正是匹配到的 `ScoreState_applyMiss` /
`applyJudgement`；`HttpClient_processRequest` 调用的正是匹配到的 curl
wrapper），以及逐位点的立即数比对。

## Scenecontrol 门控（自谱特效）

引擎内保留着一套完整的逐时刻轨道/镜头指令运行时，源自 2022 愚人节 Dynamix
联动图（`dynamix_conflict`；RTTI 名字仍在：`LogicSceneControl`、
`LogicCameraControl`、
`GameSceneVisualControlHandler::handleLogicSceneControl`）。aff 解析器对任何
谱面都会正常解析 `scenecontrol` 命令，但执行被 play-context 对象 `+0x110`
处的一个布尔标志卡住，而只有那张活动图会置位它。所有读取都经由一个 8 字节
getter：`sub_E6F768 = LDRB W0,[X0,#0x110]; RET`，约 10 个消费者：

- `sub_B77F20`（播放初始化）：先用 `"dynamix_conflict"` 字符串比较直接分配
  `img/track_black.png` + `img/track_break_mask.png`，再按该标志缩放轨道几何。
- `sub_E80B30`：触点→轨道映射；置位后改为查询变换调度对象，而非固定
  ±425/±850 轨道边界。
- `Gameplay_tryTapJudgementForTouch`（`0x109F144`）：命中测试中查询两次。

这与社区 4.x 的改法（"search immediate 264 / LDRB +0x108 后把 getter 改成
`MOV W0,#1`"）是同一家族；ARM64 上各编译单元把全部检查都收敛到了这一个
getter 调用之后。安装自谱时模块把那 8 字节原地换成 `MOV W0,#1; RET`
（`kScenecontrolGateAlwaysTrue`），走一条带校验的 `PatchTransaction`。调度为空时
消费者行为与原版收敛，官方谱不受影响；补丁失败不致命，仅特效保持休眠。
7.0.0c 之前的 profile 该偏移为 0，自动跳过。社区提到的绿蛇重映射
（`CMP W1,#2 → #4`）本轮未在 7.0.0c 上复现定位，且镜头/轨道调度并不需要它。

## 7.0.0c 对象布局漂移

基础区（`Timer`、`Gameplay`、直到 `longTouchState` 的公共 `LogicNote`
字段、`NotePosition`、`TouchLike`、`HttpRequest`、`HttpResponse`，以及
自定义谱面的整个 `Song`/`SongDifficulty`/注册表家族）未变化；这些偏移由
`src/game/GameStructs.hpp` 中的共享断言钉住。

note 家族「派生区域」在 `active`(+0x54，未动) 与 `isVoid` 之间插入了一个
指针大小的成员，其后所有派生成员整体 +8。以下均来自两版配对代码的直接
验证：

| 成员 | ≤ 6.16.8c | 7.0.0c | 证据 |
|---|---:|---:|---|
| `LogicArcNote::isVoid` | `+156` | `+164` | arc typeinfo 引用旁所有 `ldr w,[..,#0x9C]` 变为 `#0xA4`（旧偏移在新版无幸存位点） |
| arctap 子音符位置读取 | `child+120` | `child+128` | `tryTapJudgementForTouch` 判定循环 |
| `LogicHoldNote::headActivated` | `+160` | `+168` | `tryTapJudgementForTouch` 中 hold cast 后写 `v46[160]` → `v46[168]` |
| `LogicArcNote::activeNow` | `+200` | `+208` | 随 isVoid 同步移动的 hit-test 门控读取 |
| arc 运行时 x/y 浮点 | `+204/+208` | `+212/+216` | 全库唯一 `(204,208)` 浮点对访问窗口消失，仅出现一个 `(212,216)` 窗口 |

消费方统一走版本感知选择器（`src/config/AutoplayConfig.h` 中的
`cfg::autoplay::*Offset(version)`，由 `src/game/GameTypes.hpp` 应用）；活动
布局行在任意 feature 挂钩之前就依据解析出的 profile 写入。

残余风险：`LogicNote::longTouchState`(+92) 与 `playSceneCtx`(+64) 在全部
匹配函数中未见矛盾证据，但本次未能绑定到专属确立位点，暂留在共享行。

## 7.0.0c songlist / AFF 格式备注

结论来自对线上 `songlist`、konzetsu 两首新曲（`cataclysmcry` /
`deinosphainein`）以及 songlist 解析主体 `sub_CCE050` 的交叉核对：

- 难度槽位仍是 5 个。所有 `ratingClass` 都经过 `sub_1194380`
  （`return rc >= 5 ? 1 : rc`）归一，自谱家族的布局与槽数均无变化。
- 新的 Inscribed 难度挂在 `ratingClass: 3` 上，附带仅用于展示的
  `ratingClassAlias`（=1）与 `legacy11`。两个键都在 `sub_CCE050`
  内读取（字符串 xref 位于 `0xCD06F4` / `0xCD10A4`），再传入单个难度
  构造函数 `sub_8BDEE8`；缺省时默认 0/false。因此模块生成的自谱条目
  继续只写普通 `ratingClass` 即完全有效。
- 官方 `side` 取值域现在是 0..4（2 自 v4.0 epilogue 曲目、3 自 v6.0
  lephon/designant、4 首次出现在 konzetsu）。为让 raw-zip 元数据导入
  不再把它们回退成默认值，`cfg::custom_charts::kMaximumSide` 从 2 提到 4。
- AFF 新增内容全部原样透传即可：arc 颜色索引 3（`cataclysmcry_3` 的金色
  引导弧）本来就不被 normalizer 改写；timinggroup 标签在官方语法中是任意
  标识符（`deinosphainein_3` 就带 `timinggroup(tracecoleeee00)`）。运行时
  分析确认组属性匹配器只认 `noinput`、`fadingholds` 与
  `anglex<十分之一度>`/`angley<十分之一度>`，未知标签是惰性的——于是
  `AffNormalizer` 现在原样保留合法标识符形态的标签而不再丢弃（拼写为
  词法关键字如 `true` 的标签仍然拒绝）。
- 官方解析器文法本身相对 6.x 无变化。词法关键字分类器（`sub_10DC294`）
  认定的保留字仍只有 13 个（`timing`、`hold`、`arc`、`camera`、
  `scenecontrol`、`timinggroup`、`rgb`、`flick`、`arctap`/`at`、`true`、
  `false`、`designant`），没有新增命令或标志字。交叉验证：全部 8 张样例
  谱面的每一行都无需改动即可通过 `aff::CheckOfficial`（共 6877 条弧线，
  参数个数只出现 10 或 10+可选末尾正浮点，颜色 0/1/3，组名为空串或单个
  标识符）；对应的 7.0 形状用例放在
  `tests/aff_official_parser_host_test.cpp`。

安装期检查同时覆盖 `0x105F0F4` 的 BL、两个摘要守卫与 scenecontrol 门控字节。
当 `../7.0.0c/libcocos2dcpp.so` 存在时，`python tests/verify_profile.py`
会按上述精确 SHA-256 校验本 profile。
