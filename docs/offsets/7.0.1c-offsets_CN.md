语言：[English](7.0.1c-offsets.md) | 简体中文

目标：`libcocos2dcpp.so`（ARM64，已剥符号）

- SHA-256：`426ce11edb840514acf0056d9ba48b597cf30f796298461b16c4e4e113e8742d`
- Build ID：`4d0bad75646cdd051bc82d526ffb4fa99c5f6b88`

所有被消费的函数都由 `scripts/port_match.py` 从 7.0.0c 迁移。19 个目标

复跑与语义 diff 全部通过。IDA 9.3 另行确认了版本全局变量、直接调用关系、
RTTI 对象、资源加载调用点、曲目注册表全局变量与 scenecontrol getter。

## 语义确认

- `0x14AE3D4` 的版本 setter 把 Java 字符串复制到 `0x1BAA8C8` 的
  libc++ string，现有运行时识别模型可以直接沿用。
- `processLogicNotes` 从 `Gameplay +0xA0/+0xA8` 读取 note vector，调用
  `ScoreState_applyJudgement @ 0x140CFF4` 与
  `ScoreState_applyMiss @ 0x11306E0`，并引用
  `_ZTI12LogicArcNote @ 0x1B0DAC8`。
- `tryTapJudgementForTouch` 同时引用新版 Hold/Arc RTTI；ELF 相对重定位将
  唯一类型名分别绑定到 `0x1AA4C68` 与 `0x1B0DAC8`。
- `HttpClient_processRequest` 仍按 `request+0x0C` 的请求类型分派，从
  `+0x28/+0x30` 读取 body 范围，并在 GET/POST/PUT/DELETE 路径调用
  `0x1A09024` 的 curl wrapper。
- `0x16D88D8` 的小 getter 读取 `qword_1BAEB28`，确立了调用
  `find_song_by_id` 前使用的曲目注册表 owner 全局变量。
- scenecontrol getter 仍是唯一的 8 字节
  `LDRB W0,[X0,#0x110]; RET`。IDA 记录到十个调用者，其中两个来自
  `tryTapJudgementForTouch`，与 7.0.0c 一致。
- 成对比较 gameplay、play launcher、chart path 与 availability 函数后，
  所有被消费的对象位移均保持不变。因此 7.0.1c 复用 7.0.x note 派生布局
  （`isVoid +0xA4`、`activeNow +0xD0`、运行时 X/Y
  `+0xD4/+0xD8`、hold head `+0xA8`）以及未变的自定义谱面 Song 布局
  （`remote_pack +0x1C0`、难度表 `+0x228`、lock `+0xF0`）。
- `libfmodProvider.so` 仍在 `0x25FFC` 导出大小为 `0x3A0` 的
  `_ZN24AudioProviderFMODAndroid7loadBGMEPKci`。

## 复现命令

```bash
python scripts/port_match.py locate ../7.0.0c/libcocos2dcpp.so \
  ../7.0.1c/libcocos2dcpp.so scripts/port_match_7001c_spec.json
python scripts/port_match.py diff ../7.0.0c/libcocos2dcpp.so \
  ../7.0.1c/libcocos2dcpp.so scripts/port_match_7001c_spec.json
python tests/verify_profile.py 7.0.1c
python tests/run_host_tests.py
./build.ps1 --rebuild --rel
```

`tests/verify_profile.py` 固定校验精确 SHA-256、全部 Hook prologue、songlist
调用点、两个摘要守卫、scenecontrol getter 与全部运行时补丁原值。
