# Arcaea 7.0.255c 偏移证据

语言：[English](7.0.255c-offsets.md) | 简体中文

目标：`libcocos2dcpp.so`（ARM64，已剥符号）

- SHA-256：`72e42cb4925655ecfef98bf2dbf92a5ac05145eb005a531c96c11b927a46e6dc`
- Build ID：`c8434354f4ad8f78481f592cc0c215202a58a056`
- FMOD provider SHA-256：`3803aad5303e8816573bb110ea69f5022df7291b7d0e7c509d5f2ce73e3927d3`

19 个被消费函数中的 18 个由 `scripts/port_match.py` 从 7.0.1c 迁移，均为唯一
共识候选，且函数边界与 7.0.1c 逐字节一致；已固定在
`scripts/port_match_70255c_spec.json`，固定地址复跑与语义 diff 全部通过。
`ShowJudgementEffectAtNote` 在 7.0.255c 中被重写（0x598 -> 0xAC8 字节，新
prologue），其固定地址改用 pinned 地址处的精确掩码字节确认。IDA 另行确认了
版本全局变量、直接调用关系、RTTI 对象、资源加载调用点、曲目注册表全局变量
与 scenecontrol getter。

## 语义确认

- `0xF78E74` 的版本 setter 把 Java 字符串复制到 `0x1BDFF80` 的
  libc++ string，现有运行时识别模型可以直接沿用。
- `processLogicNotes` 从 `Gameplay +0xA0/+0xA8` 读取 note vector，以与
  7.0.1c 相同的 Tap/Flick/Long/Arc/Camera/SceneControl 分派逻辑遍历，调用
  `ScoreState_applyMiss @ 0xE19784` 与 `ScoreState_applyJudgement @
  0xB4DB58`，并经 `__dynamic_cast` 引用 `_ZTI12LogicArcNote @ 0x1ACC9F0`。
  miss 窗口的 timer 读取保持共享 Timer 镜像的
  `+0x20/+0x28/+0x2D/+0x34` 位移。
- `tryTapJudgementForTouch` 同时引用 Hold/Arc 两处 RTTI
  （`0x1AAAB10` / `0x1ACC9F0`）；ELF 相对重定位把唯一类型名
  `"13LogicHoldNote" @ 0x4BEE2B`、`"12LogicArcNote" @ 0x501E07` 分别绑定
  到这两个 `_ZTI` 对象。
- `ShowJudgementEffectAtNote` 被重写：函数边界从 `0x598` 增长到 `0xAC8`
  字节，帧布局也变了。但 `img/hit_pure.png` / `img/hit_far.png` /
  `img/hit_lost.png` / `EARLY` / `LATE` 字符串集合完全一致，且两个调用者
  恰好是 `note_effect_on_miss +0x11C` 与 `note_effect_on_judgement +0xB8`
  ——与 7.0.1c 的调用点完全相同，函数身份由此确立。
- `HttpClient_processRequest` 仍按 `request+0x0C`（经 `response+0x10`
  取得）的请求类型分派，从 `+0x28/+0x30` 读取 body 范围，在
  GET/POST/PUT/DELETE 路径调用 `0xD2F7D8` 的 curl wrapper（10036 =
  `CURLOPT_CUSTOMREQUEST`、10015 = `CURLOPT_POSTFIELDS`），并把状态码与
  成功标志写回 `response+0x50` / `response+0x18`。
- 小 getter（`sub_161CB34`）读取 `0x1BE7028` 的全局变量并解引用
  `+120`、`+24`——与 7.0.1c 对 `qword_1BAEB28` 的链路完全一致，确立了调用
  `find_song_by_id` 前使用的曲目注册表 owner 全局变量；迁移后的
  `find_song_by_id` 仍在 `arg+24` 做同样的 map 查找。
- scenecontrol getter 仍是全二进制唯一的 8 字节
  `LDRB W0,[X0,#0x110]; RET`，位于 `0x17B0140`。
- songlist 资源打开函数是迁移后的 cocos2d-x `FileUtilsAndroid` asset
  路径（13 个锚点窗口中 12 个匹配，`+0x200` 处 `BL; MOV X20,X0; CBZ X0`
  的调用点模式逐字一致）；函数体从 `0x418` 增长到 `0x744` 字节，调用点
  位移未变。
- 成对比较 gameplay、play launcher、chart path 与 availability 函数后，
  所有被消费的对象位移均保持不变。因此 7.0.255c 复用 7.0.x note 派生布局
  （`isVoid +0xA4`、`activeNow +0xD0`、运行时 X/Y
  `+0xD4/+0xD8`、hold head `+0xA8`）以及未变的自定义谱面 Song 布局
  （`remote_pack +0x1C0`、难度表 `+0x228`、lock `+0xF0`）。
- `libfmodProvider.so` 仍在 `0x3A4E0` 导出大小为 `0x3A0` 的
  `_ZN24AudioProviderFMODAndroid7loadBGMEPKci`。

## 复现命令

```bash
python scripts/port_match.py locate ../7.0.1c/libcocos2dcpp.so \
  ../7.0.255c/libcocos2dcpp.so scripts/port_match_70255c_spec.json
python scripts/port_match.py diff ../7.0.1c/libcocos2dcpp.so \
  ../7.0.255c/libcocos2dcpp.so scripts/port_match_70255c_spec.json
python tests/verify_profile.py 7.0.255c
python tests/run_host_tests.py
./build.ps1 --rebuild --rel
```

`tests/verify_profile.py` 固定校验精确 SHA-256、全部 Hook prologue、songlist
调用点、两个摘要守卫、scenecontrol getter 与全部运行时补丁原值。
